# Robotics_Kernel — 机器人研发技术知识库

## 一、项目目的

本知识库分两条线：

**技术线**：系统性沉淀机器人研发过程中遇到的技术问题与解决方案。覆盖端侧AI部署、语音交互Pipeline、RAG系统、通信架构、数据工程、模型原理、多模态业务、运维自动化等方向。目标是把踩过的坑、跑通的方案、理解清楚的原理，变成可复用、可检索的结构化知识。

**哲思线**：记录生活与工作中由佛学、道德经、哲学、心理学引发的真实感悟。不是摘抄和理论复述，而是"这件事让我想到了什么、印证了什么、改变了什么"的实践沉淀，追求知行合一。

## 三、技术文章生成规范

本规范适用于 **技术线** 的文章输出。哲思线文章格式自由，参见 `个人哲思/README.md`。

### 3.1 文件命名

```
YYYY-MM-DD_<简短主题标识>.md

规则：
- 日期部分固定为 YYYY-MM-DD 格式
- 主题标识用中文书写，专业术语/型号/缩写（如 ASR、TTS、INT4、Qwen 等）可用英文
- 用短横线 `-` 连接多段关键词

示例：
 2026-06-05_端侧AI开发板选型指南.md
 2026-06-07_qwen3-tts-0.6b-部署基线报告.md
 2026-06-10_语音交互流水线-三类模型部署策略.md
```

### 3.2 正文结构

**唯一强制要求：文章开头必须是 H1 标题 + 核心摘要（≤ 150 字）。**

H1 标题：用 `# ` 开头，写清楚文章主题，与文件名对应。
核心摘要：用 2～4 句话说清楚这篇文章讲什么、结论或结果是什么。

**其余结构根据内容类型灵活组织，不做强制要求。** 以下是常见的参考段落，按需取用：

- **问题背景**：环境信息、触发条件、已尝试的路径及其局限
- **解决方案 / 核心机制**：思路先行，再展开步骤、命令、配置或原理；标注避坑点
- **验证结果**：验证方式 + 量化数据（有数字尽量写数字）
- **知识点梳理**：适用于概念介绍类文章，可用对比表、图示、层次拆解等方式呈现
- **延伸思考**：局限性、横向对比、下一步方向（可选）
- **参考资料**：文档、博文、Issue、论文链接

> AI 在生成文章时应根据内容性质自行判断用哪些段落、用什么顺序，不必套模板。
> 问题排查类文章侧重背景→方案→验证；知识介绍类文章侧重核心机制→原理拆解→应用场景。

---

### 3.3 写作原则

1. **先摘要，后细节**：核心结论放最前面，细节在正文展开，不在摘要里复述正文。
2. **可复现**：涉及操作步骤的，要具体到能跑通，不留"大家应该都懂"的空白。
3. **数字说话**：性能、资源占用、准确率等有数字就写数字，避免"较快""明显提升"等模糊表述。
4. **工程视角**：优先解释"为什么这样做"，不只写"怎么做"。
5. **精简不冗余**：结构服务于内容，不为凑格式而强行填充段落。
6. **标题语言**：正文各级标题（`#`、`##`、`###` 等）一律使用中文，专业术语（如 ASR、LLM、TTS、RK3588、CUDA、INT8 等缩写/型号）除外，不得用纯英文短语做标题。
