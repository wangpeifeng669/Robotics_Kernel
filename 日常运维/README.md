# 日常运维

## 模块定位

本模块沉淀机器人/端侧开发板在**日常部署、版本发布、故障排查**过程中遇到的工程性运维经验。聚焦"系统层面"的稳定性、自动化与可恢复性——和具体业务模型（ASR/LLM/TTS/RAG）解耦，但又服务于所有这些业务的平稳运行。

---

## 核心主题

| 主题 | 说明 |
|---|---|
| 端侧打包与发布 | deb / 镜像 / 量产烧录的体系设计；增量更新通道 |
| 系统与依赖 | Python venv、ONNX 运行时、systemd 自启、系统库与驱动 |
| 故障排查 | 服务挂掉、依赖缺失、版本不匹配、磁盘/内存异常的快速定位 |
| 自动化脚本 | 装机脚本、备份与回滚、健康检查、CI 衔接 |

## 写作原则

1. **场景先行**：文章先写"我在什么环境下遇到了什么问题"，再展开做法。
2. **可复现命令优先**：能贴命令的不放截图，能贴路径的不放描述。
3. **标注坑点**：系统层面的坑往往是"少一个文件"或"多挂一个钩子"，写明避坑口径。
4. **与业务解耦**：本模块不写"哪个模型怎么调"，只写"在板上怎么让任何服务稳定跑起来"。
