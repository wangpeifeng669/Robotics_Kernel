# 内存基础-类型速度与端侧取舍

**核心摘要**：内存条上标的"3200"既不是容量也不是频率，是每秒搬运次数（MT/s）。带宽 = MT/s × 位宽 ÷ 8，内存商标 MT/s、我们算 GB/s，中间隔着 8 倍。所有高带宽内存（HBM、3D 堆叠）靠的是"加宽"不是"跑快"——HBM2E 的 pin 比 LPDDR5X 还慢一半，位宽宽 16 倍。带宽、功耗、成本三者互相冲突，端侧只能取舍：RK3588 用 LPDDR4X 的 34 GB/s 跑语音链路，需求越过 50 GB/s 就必须换堆叠内存。

> 数据口径：带宽换算表按公式自算，非引用；RK3588 兼容性引瑞芯微官方 DDR 设计建议；RK1828 内存代次与带宽官方未给，本文不引用具体数字。

---

## 一、先分清三件事：容量、带宽、延迟

反直觉的事实：**内存条上贴的"3200"不是容量，也不是时钟频率**，它指每秒钟有多少次数据搬运机会，单位 MT/s（每秒百万次传输）。

用仓库比喻，三件事互不相同：

| 概念 | 比喻 | 决定什么 |
|---|---|---|
| **容量** | 仓库有多大（8GB / 16GB） | 能装多少货 |
| **带宽** | 门有多宽 + 叉车多快（GB/s） | 能多快把货拉出来 |
| **延迟** | 下单到送货上手（ns） | 急不急 |

很多文章把三者混着讲，越看越糊。**端侧部署最在意带宽**，因为大模型的瓶颈就卡在"权重太大，一次读不完"。

---

## 二、带宽怎么算：一行公式和三个单位

```
带宽 GB/s = 数据速率(MT/s) × 数据位宽(bit) ÷ 8
```

最容易错的是单位，差 8 倍：

| 单位 | 含义 | 谁在用 |
|---|---|---|
| **MT/s** | 每秒传输次数（兆次） | 内存标称，如 4266MT/s |
| **Gbps** | 每秒**比特**数（小写 b） | GDDR6、HBM |
| **GB/s** | 每秒**字节**数（大写 B） | 我们算带宽用的 |

内存商家标 MT/s 和 Gbps，我们算的是 GB/s，**必须除以 8**。

### 按公式算一遍（64bit 位宽）

| 规格 | 数据速率 | 位宽 | 带宽 |
|---|---|---|---|
| DDR4-3200 | 3200 MT/s | 64 bit | 25.6 GB/s |
| LPDDR4-3200 | 3200 MT/s | 64 bit | 25.6 GB/s |
| LPDDR4X-4266 | 4266 MT/s | 64 bit | **34.1 GB/s** |
| LPDDR5-6400 | 6400 MT/s | 64 bit | 51.2 GB/s |
| LPDDR5X-8533 | 8533 MT/s | 64 bit | **68.3 GB/s** |
| LPDDR5T-9600 | 9600 MT/s | 64 bit | 76.8 GB/s |
| GDDR6-18Gbps（单颗） | 18000 MT/s | 32 bit | 72.0 GB/s |
| HBM2E-3.6Gbps | 3600 MT/s | 1024 bit | **460.8 GB/s** |

---

## 三、高带宽靠"加宽"，不靠"跑快"

对比最后两行，这是本文最重要的一条：

- **LPDDR5X**：pin 跑 8533Mbps，位宽 64 bit → 68.3 GB/s
- **HBM2E**：pin 只有 3600Mbps（**比 LPDDR5X 还慢一半**），位宽 1024 bit（**宽 16 倍**）→ 460.8 GB/s

**高带宽内存的共同秘密是加宽，不是提速。** 原因有两条：pin 速率一旦跑高，信号在硅片或电路板上走远一点就失真，功耗也爆炸；而位宽可以堆——HBM 用 TSV（硅通孔）在芯片内部垂直连线，能做到 1024 位；LPDDR 挂在 PCB 上，位宽卡在几十位。

**反推一遍更有体感**：要 500 GB/s，用 LPDDR5X 的 8533Mbps 单通道，理论上得堆到 `500×8÷8.533 ≈ 469 bit`——远超任何 SoC 能提供的位宽。**这就是端侧跑大模型必须换架构的原因，不是把 LPDDR 频率调高就能解决。**

---

## 四、取舍三角：带宽、功耗、成本互相冲突

要一个就得舍一个：

| 想要 | 代价 |
|---|---|
| **更高带宽** | 电压升高 → 功耗发热上升；位宽加宽 → 芯片面积和成本上升 |
| **更低功耗** | 必须降电压 → 信号余量变小 → 速率和位宽都上不去 |
| **更低成本** | 只能用成熟工艺、单通道、PoP 而非 3D 堆叠 → 带宽天花板低 |

端侧的具体处境是三重夹逼：

1. **电池 / 散热罩住功耗**——机器人是插座供电，但整机发热敏感
2. **BOM 敏感**——一颗 SoC 贵 100 块，量产一万台就是 100 万
3. **体积受限**——3D 堆叠封装良率低、成本高，不是所有产品都愿意用

所以端侧的答案是"在够用范围内，把功耗和成本压到最低"：

- **RK3588 选 LPDDR4X**（34.1 GB/s 理论）——语音链路模型几十 MB，够用，换低功耗和便宜
- **要跑 7B 就得上堆叠**——需求越过 50 GB/s 这条线，LPDDR 无论哪一代都到不了

## 五、同一场取舍的两个答案：RK3588 vs RK1828

| 维度 | RK3588 | RK1828 |
|---|---|---|
| **定位** | 主控 SoC | **AI 协处理器**（自己不能当主控） |
| **内存位置** | PCB 外置颗粒 | **片上 3D 堆叠** |
| **内存类型** | 兼容 LPDDR4 / LPDDR4X / **LPDDR5** | 官方**只写"内置 DRAM"，未标 LPDDR 代次** |
| **容量** | 4～32GB（板级可配） | 5GB（RK1820 是 2.5GB） |
| **带宽** | LPDDR4X-4266 → **34.1 GB/s** 理论 | 官方未给实测；产业口径"数百 GB/s 级" |
| **NPU 算力** | 6 TOPS | 20 TOPS |
| **互联** | — | PCIe 2.0 x1 / USB 3.0 挂主控 |
| **发布时间** | 2022 前后 | 2025-07-17 首发，2026 量产 |

三个必须说清的点：

**1. 你的 LubanCat-4 实际是 LPDDR4X。** 野火官方规格表写 `LPDDR4X-4/8GB`，不是 DDR4。RK3588 控制器同时兼容 LPDDR4 / LPDDR4X / LPDDR5，所以"支持 DDR5"这种说法也是错的。

**2. RK1828 的 5GB 不是 LPDDR，也不能引用具体带宽数字。** 瑞芯微官网产品页原文只写"内置多核 RISC-V CPU 与 2.5/5GB DRAM"，**没写 LPDDR 代次**。二手来源在这件事上互相打架：同一家的两篇文章，一篇说 LPDDR5X + 102 GB/s，另一篇说 LPDDR4X + 1024 GB/s，**差 10 倍且自相矛盾**。这类数字一律不引用。

**3. 堆叠内存买的是带宽，不是省电。** 兆易创新的 3D 堆叠方案公开信息：15/17nm、逻辑芯片置于存储模组下方靠基板、带宽 ≥500 GB/s（接近 HBM2E）、功耗约为台系方案一半、混合键合由长电/通富负责、晶圆由长鑫代工，业界定位"类 HBM 自研方案"。

**LPDDR5X 顶格 68.3 GB/s，堆叠到 500 GB/s 量级是 7.3 倍。** 所以：

> **RK1828 不是"更强的 NPU"，是"自带 500GB/s 内存的 NPU"。** 它解决的是"权重读不过来"，不是"算得不够快"。

## 六、落到自己板子上的三条

### 1. 带宽只能测，不能推

标称值是理论峰值，实际通常打 6～7 折：

```bash
# 板端实测可用带宽
dd if=/dev/zero of=/tmp/t bs=1M count=2048 oflag=direct
# 更准的三角测量：装 stream / lib-bandwidth，跑 memcpy 带宽
```

### 2. 文档写 LPDDR4X 不等于你板上是 LPDDR4X

野火文档写 LubanCat-4 = LPDDR4X，但同系列 BTB 核心板能选到 16GB，RK3588S 另有 LPDDR5 版本。**上板读一次，别按文档猜：**

```bash
lshw -class memory        # 看颗粒 manufacturer / model
dmesg | grep -i -E "lpddr|dram"
```

顺带一个硬件信号：LPDDR5 引入了 WCK 独立时钟，SoC 侧会切电压档位（DVFSC：0.9V / 1.05V）。如果你的板真是 LPDDR5，而你按 4X 的时序在调，那就是白折腾。

### 3. 把带宽换算成 token/s 上限

大模型 decode 阶段每生成 1 个 token，要把**整个权重从内存读一遍**：

```
token/s 上限 ≈ 可用带宽 ÷ 权重体积
```

实测示例：可用带宽 22 GB/s（= 34.1 × 0.65 打折）、Qwen2.5-1.5B INT4（权重 0.75GB）、调度效率 0.6 → **17.6 token/s 理论上限**。

**这个数的用法是和板子实测 TPS 对账：**
- 实测明显低于它 → 瓶颈不在算力也不在带宽，去查算子是否走 CPU fallback、DMA 是否对齐
- 实测接近它 → 带宽已经吃满，只能换 INT4 或上堆叠内存

## 七、一页速查

```
带宽 GB/s = 数据速率 MT/s × 位宽 bit ÷ 8

LPDDR4X 不是 LPDDR4 的下一代，是它的低压分支（1.1V→0.6V I/O）
3D 堆叠是封装技术，不是内存代次

LPDDR5X   8533Mbps ×   64bit =  68.3 GB/s
HBM2E     3600Mbps × 1024bit = 460.8 GB/s   ← pin 慢一半，位宽宽 16 倍
→ 高带宽靠"加宽"，不靠"跑快"

可用带宽 ÷ 权重体积 = token/s 上限

查自己板子:  lshw -class memory  |  dmesg | grep -i lpddr
测真实带宽:  dd if=/dev/zero of=/tmp/t bs=1M count=2048 oflag=direct
```
