# RKNN-Toolkit2-2.3.2-量化打包类型与选型

**核心摘要**：2.3.2 的 `config` 只认五个 `quantized_dtype` 字符串，加上不量化的 FP16，数值路径一共六条。决定能打哪一种的不是模型，而是 `target_platform`——RK3588 只放行 FP16、`w8a8`、`w16a16i`、`w16a16i_dfp` 四条，`w8a16` 和 `w4a16` 在这一步就被拒绝。选型顺序应是：先看芯片菜单，再看任务能容忍的误差，最后才看体积。

> **环境与口径**
> 工作区：`/data/work/peifeng`
> 工具链：`rknn-toolkit2==2.3.2`（版本锁定见 `deploy/versions.lock`）
> 探查方式：对已安装的 2.3.2 调用 `rknn.config(target_platform=..., quantized_dtype=...)`，尚未加载模型
> 日期：2026-09-30

一套 toolkit 打多种芯片。芯片在 `rknn.config` 的 `target_platform` 里传入，打包类型是否放行由这一步决定，与后面加载的是 HiFi-GAN 还是别的 ONNX 无关。

---

## 一、名字怎么读

`quantized_dtype` 用 `w` 和 `a` 把权重、激活拆开：

| 字母 | 含义 |
|---|---|
| `w` | weight，权重存成几位 |
| `a` | activation，推理时特征图用几位 |

`w8a8` 是权重 8 位、激活也是 8 位。口语里的 INT8，在这套工具链里就是它。`w8a16` 仍是 8 位权重，激活放宽到 16 位。体积大头在权重，激活位宽主要影响特征图的动态范围和运行时带宽。

关闭量化时不填 `quantized_dtype`，走 `do_quantization=False` 且 `float_dtype="float16"`。2.3.2 的浮点路径只有 FP16，没有 FP32 的 RKNN。

---

## 二、2.3.2 登记了哪些类型

`config` 接受的 `quantized_dtype` 只有五个字符串：

| 类型 | 权重 | 激活 | 在选型里的位置 |
|---|---|---|---|
| `w8a8` | 8 位 | 8 位 | 默认量化。权重和特征图都压到 8 位 |
| `w8a16` | 8 位 | 16 位 | 权重大小接近 `w8a8`，激活少截断 |
| `w16a16i` | 16 位整数 | 16 位整数 | 位宽接近 FP16，体积也接近 FP16 |
| `w16a16i_dfp` | 16 位动态定点 | 16 位动态定点 | 仍是 16 位，缩放可随张量变 |
| `w4a16` | 4 位 | 16 位 | 权重更小，激活保持 16 位 |

再加上不量化的 FP16，数值路径一共六条。`w4a8` 不是合法名字，传入会报 `Invalid quantized_dtype`。旧 changelog 里出现过 `w4a8`，2.3.2 的校验列表里已经没有它。

`quantized_method`（`channel` / `layer`）和 `quantized_algorithm`（`normal` / `mmse` / `kl_divergence` / `gdq`）是同一种类型内部的刻度，不是新的打包类型。混合量化是敏感层留 FP16，基础类型仍然必须是该芯片放行的那一个。

---

## 三、传入芯片之后，菜单会收窄

下面是 2.3.2 上 `config` 的放行结果。`yes` 表示这一步接受，还不代表模型里每个算子都能留在 NPU。

| 平台 | FP16 | w8a8 | w8a16 | w16a16i | w16a16i_dfp | w4a16 |
|---|---|---|---|---|---|---|
| RK3588 | 是 | 是 | 否 | 是 | 是 | 否 |
| RK3576 | 是 | 是 | 否 | 是 | 是 | 是 |
| RK3568 / RK3566 | 是 | 是 | 否 | 是 | 是 | 否 |
| RK3562 | 是 | 是 | 是 | 是 | 是 | 否 |
| RK2118 | 是 | 是 | 否 | 是 | 是 | 否 |
| RV1126B | 是 | 是 | 否 | 是 | 是 | 是 |
| RV1106 / RV1106B / RV1103 / RV1103B | 是 | 是 | 否 | 是 | 是 | 否 |

RK3588 因此只有四条：FP16、`w8a8`、`w16a16i`、`w16a16i_dfp`。`w8a16` 和 `w4a16` 在工具链里有名字，传了 `rk3588` 就在 `config` 被拒绝，到不了校准和 `build`。这块板上的所有模型都是这四条，不是某一个工程单独少了选项。

`w8a16` 在这张表里只对 RK3562 放行。`w4a16` 只对 RK3576 和 RV1126B 放行。

## 四、w8a8 和 w8a16

两者权重都是 8 位，模型文件大小通常接近，大约是 FP16 权重体积的一半。差别在激活。

卷积、反卷积和残差加的中间值往往比权重更散。`w8a8` 把这些特征图也收成 8 位，离群值会被夹掉，误差沿网络往后叠。`w8a16` 让特征图留在 16 位，权重仍然是 8 位，所以它是「体积差不多、激活少受伤」的那一档，不是另一种更小的 INT8。

代价是激活缓冲和带宽大约比 `w8a8` 宽一倍。分类、检测若 `w8a8` 已经落在指标预算内，不必为了名字升到 `w8a16`。波形、未归一化的回归值、注意力分数，往往先死在激活位宽上，这时 `w8a16` 才是该试的下一档。

源工程的 HiFi-GAN 生成器是这个差别的一个实例。同一份 ONNX、同一段对数梅尔、目标 RK3588：

| 打包 | 体积 | 相对 onnxruntime 的最大绝对误差 | 余弦 |
|---|---|---|---|
| FP16 | 28.6 MiB | 1.890e-02 | 0.999993 |
| w8a8 | 14.5 MiB | 1.432 | 0.948 |

参照波形被 `tanh` 压在 `[-1, 1]`。最大绝对误差 1.43 已经接近满幅对翻，余弦 0.948 对应的波形误差大约是 10 dB 量级，不能当声码器。接着按上面的逻辑改打 `w8a16`，`config` 直接拒绝。两次校准记录分别是 `deploy/l1_hifigan/records/05_quant_int8.md` 与 `06_quant_w8a16.md`。这次校准是合成梅尔，只说明数值掉点，不能换成听感结论。

## 五、一般怎么选

先看芯片菜单，再看任务能容忍的误差，最后才看体积。顺序反了就会在 RK3588 上要求一个不存在的 `w8a16`。

1. **FP16 做功能基线。** 图能跑、算子没有整网退回 CPU、误差相对 onnxruntime 可接受，再开量化。FP16 已经错，量化只会更错。
2. **要体积或带宽，且任务允许掉点时用 `w8a8`。** 它是默认值，也是唯一的 8 位激活。分类和检测经常停在这里。
3. **`w8a8` 掉出预算，芯片又有 `w8a16` 时，先换 `w8a16`。** 权重大小变化不大，激活范围放开。这是 `w8a8` 和全 16 位之间的一档。
4. **芯片没有 `w8a16`（RK3588 就是这样）时，下一档是 `w16a16i`。** 权重也回到 16 位，文件大小接近 FP16，换来的是激活和权重都少截断。它补的是精度，不是 `w8a8` 那种体积。
5. **`w16a16i` 仍溢出或张量范围随样本剧烈变化时，再试 `w16a16i_dfp`。** 位宽不变，变的是定点缩放。
6. **`w4a16` 只在芯片放行、且权重占内存主体时考虑。** 激活仍是 16 位。RK3588 没有这条。
7. **基础类型仍然不够，再做混合量化。** 优先把第一层、最后一层、归一化、声码器输出层留在 FP16。这是修补，不是第六种 `quantized_dtype`。

同一条 `w8a8` 里还可以换 `channel` / `layer` 和 `normal` / `mmse`。那些是刻度，替代不了芯片没放开的位宽。
