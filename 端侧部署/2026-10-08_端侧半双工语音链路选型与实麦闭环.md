# 端侧半双工语音链路选型与实麦闭环

**核心摘要**：四段模型同时驻留 RK3588，实麦三轮都在判停后 **0.84–0.88 秒**出声。链路按时间顺序是采音→端点→识别→生成→合成→播放，加载只在启动时做一次，NPU 不并行、上一段结束才进下一段。听写和合成都在一百毫秒量级，用户可感的 0.85 秒主要花在大模型吐字（12.1–12.4 token/s）。常驻内存停在 Python 730 MB + 大模型 1725 MB，合计约 **2.46 GB**，约占 7.7 GiB 板子的三分之一。三句全部识别成功；同一句问了两次回答不一致、且每轮预填 token 数几乎不变，说明当前只送本句、不带上一轮对话——多轮记忆没有测到，因为根本没送历史。

> **环境与口径**
> 板子：Embedfire LubanCat（RK3588，4×A76 + 4×A55，RKNPU v2，内存约 7.7 GiB）
> 日期：2026-10-08（东八区）
> 原始记录：`deploy/voice/logs/20261008-103755.jsonl`
> 入口：`python3 deploy/voice/profile_serve.py`
> 频率：A55 1.8 GHz，A76 2.352 GHz，NPU 1.0 GHz（全程定频，无降频）；DDR 空闲 528 MHz，生成和合成时升到 1848 MHz
> 口径：判停后出声 = 波形送进播放队列的时刻 − 端点判停的时刻。含关麦到识别之间的空档，不含用户说话本身，也不含播放时长
> 本次测的是记时入口：单麦、不唤醒、半双工、按阶段采样。正式入口 `serve.py` 为阵列麦 + 「小艺小艺」唤醒，模型同一套，那条路径本次未计时

## 一、链路选了什么，跑在哪

链路按时间顺序是：采音 → 端点 → 识别 → 生成 → 合成 → 播放。加载只在启动时做一次，某一段失败就把已经打开的关掉。NPU 不并行，上一段结束才进下一段。

| 段 | 选用 | 跑在哪 | 不用的那一档 |
|---|---|---|---|
| 端点 | Silero，官方 ONNX `silero_vad_op18_ifless.onnx` | CPU，ONNX Runtime | `silero_vad_fp16.rknn`。单帧已约 0.3 ms，搬上 NPU 省下约 1 ms，抵不上每 32 ms 跟识别、合成抢一次队列 |
| 识别 | SenseVoice-Small int8，`asr_onnx_pkg/model.int8.onnx` | 前向 ONNX Runtime（CPU），CTC 贪心在图外 | 测量链路的 `sensevoice_fp16.rknn`。图时间维冻在 64 帧，短句要补齐，超长只能失败 |
| 生成 | Qwen2.5-1.5B-Instruct，`..._W8A8_RK3588.rkllm` | NPU 算线性层，CPU 做分词、采样和 KV，常驻子进程 | 更大的模型。1.5B、W8A8 是这块板带宽账上还能对话的一档 |
| 合成 | 中文 VITS（icefall / aishell3）：`front.onnx` + `flow_decoder.rknn`（FP16） | 前段 CPU，flow 和声码器 NPU | HiFi-GAN。声码器该上 NPU、W8A8 保不住音质，本链路声码器就是这套 VITS 的解码器 |
| 采音 | Bothlent UAC，`hw:3,0`，16 kHz，单声道 | 无模型 | 板载声卡这一路没有麦的信号 |
| 播放 | es8388，`hw:2,0`。合成 8 kHz，播出前拉到声卡速率 | 无模型 | UAC 没有播放端 |

端点规则与测量链路相同：概率升过 0.5 算开口，降到 0.35 以下再连续静音 100 ms 算说完。一帧 512 点，预算 32 ms。100 ms 落在帧网格上，实测静音音频是 128 ms（4 帧）。这段嵌在「等用户说完」里，不另加进判停之后的出声时间。

生成参数：`max_context=2048`，`max_new_tokens=128`，`top_k=20`，`top_p=0.9`，`temperature=0.7`，`repeat_penalty=1.1`，遇 EOS 即停。测量二进制忽略 EOS、把 token 凑满，那是核对吐字速率；对着人说话必须停在句末，否则喇叭会把上限念完。每轮提示前固定加一句「只用简体中文口语回答，禁止出现英文字母，不要列点。」——声码器词典没有拉丁字母，答出英文这一轮就播不出来。

播放结束后再留 0.2 s，让喇叭余响散掉，下一轮才不会把自己的声音当成用户开口。

## 二、选型时已经算过的三笔账

### 生成速度由带宽决定

W8A8 权重大约 1.5 GB。每吐一个 token 要把权重再从 DDR 读一遍，算力在这一步是富余的。按 20 GB/s 的规划带宽，账面约 **13 token/s**。10 月 5 日只驻留大模型、凑满吐字时测到 **14.6 token/s**，有效带宽约是这块板 DDR 峰值的七成。本次实麦是短回答、遇 EOS 即停，吐字 **12.1–12.4 token/s**——比单独凑满慢一档，数量级仍是带宽账，不是算力账。中文在这个词表上约 1 个 token 对应 1 到 2 个字，回答每多几个字，出声就多几百毫秒。

### 上下文窗口按内存裁，不按模型上限

模型训练上限是 128K。KV 按 FP16 约每 token 28 KiB，开满 128K 比权重还大。语音对话把窗口收到 2048。10 月 5 日测量用 4096，大模型进程高水位约 1782 MB；本次 2048，实麦停在 1725 MB——差的是窗口，不是泄漏。

系统提示、历史、本轮输入、已经生成的字占的是同一个窗口。当前实现每轮只送固定前缀加本句，预填长度停在 54–55 个 token，历史没有累进去。

### 识别换成动态时间维

10 月 5 日的 FP16 RKNN 前向中位 165 ms、后处理约 17 ms，但图长冻在 64 帧：100 ms 的句中停顿会被当成说完，切给识别的是被截短的那一段；超长则整段失败。实麦改用 sherpa-onnx 的 SenseVoice-Small int8，时间维动态、短句不补齐。语言中文，文本归一化打开。特征仍是 LFR，这次带 CMVN（记时字段 `lfr_cmvn`）。测量包里的 RKNN 还在，实麦入口不加载它。

## 四、三轮实麦

| 轮次 | 识别 | 回答 | 判停后出声 | 识别 | 生成（预填 / 吐字） | 合成 | 播放 |
|---|---|---|---|---|---|---|---|
| 1 | 今天去干嘛？ | 我去图书馆看书。 | 856 ms | 121 ms | 613 ms（281 / 323，4 token，12.37 /s） | 49 ms | 2960 ms |
| 2 | 今天去干嘛？ | 今天打算做什么呢？ | 837 ms | 114 ms | 658 ms（243 / 407，5 token，12.29 /s） | 33 ms | 2536 ms |
| 3 | 我声音这么小。 | 那你试着大声一些吧！ | 884 ms | 104 ms | 721 ms（217 / 497，6 token，12.08 /s） | 32 ms | 2501 ms |

出声时间里，生成占 72%、79%、82%。识别约 110 ms，合成约 35 ms。生成进程和 Python 之间的交接约 8 ms（墙钟 − 预填 − 吐字）。

识别内部：前向 87–96 ms，CTC 后处理 0.3–0.5 ms，剩下约 17–28 ms 是滤波器组。10 月 5 日 RKNN 前向中位 165 ms、后处理 17 ms；本次句子更短、又走动态图，前向降到 100 ms 以内，后处理可忽略。三句都没有识别错误，第三句说话人自己觉得声音小，文本仍是完整的「我声音这么小。」

预填都是 54 或 55 个 token。10 月 5 日短句公式 `prefill_ms ≈ 7.08e-4·N² + 3.04·N + 41` 在 N=54 时约 207 ms。第三轮开始时 DDR 已在 1848 MHz，预填 217 ms，与公式同档；前两轮预填开始时 DDR 还在 528 MHz，281 ms 和 243 ms 里有升频的等待。

合成第一轮 84 帧、桶长 160，声码器 37 ms；后两轮约 72 帧、桶长 80，声码器 20 ms。前段稳定在 11–13 ms。10 月 5 日同驻时整句中位 51 ms，本次短句落在 32–49 ms。第一轮送进播放队列多等了 52 ms，后两轮约 7 ms。

听的循环没有成为瓶颈：

| 项 | 三轮 |
|---|---|
| 开麦到第一帧 | 167 / 163 / 163 ms |
| 听帧 p50 / p95 / 最大 | 约 2.0 / 4.0 / 4.6 ms，预算 32 ms |
| 端点前向 p95 | 3.5–3.6 ms |
| 判停滞后（静音墙钟 − 静音音频） | −0.5 / −0.3 / +0.2 ms |
| 人声音频 | 1184 / 1120 / 1152 ms |

开麦这一百多毫秒发生在上一轮播完之后、下一轮开始收帧之前，不进「判停后出声」。听帧 p95 只用了预算的约八分之一。判停滞后在 1 ms 以内，端点贴着实时，没有把静音多等一轮。

## 五、资源和频率

三轮之后 RSS 停在 Python 730.3 MB、大模型 1725.2 MB，合计 2455 MB。高水位和当前占用相同，没有尖峰，也没有一轮比一轮高。7.7 GiB 的板子上，这条常驻链路约用掉三分之一。10 月 5 日测量进程把四段的计时脚手架也算进去，高水位中位 2924 MB；实麦入口更瘦，不是模型变小了。

| 阶段 | Python CPU | 大模型进程 CPU | 说明 |
|---|---|---|---|
| 空闲 5 s | 10 ms | 0 | 模型已加载，没有推理 |
| 听（墙钟 8–15 s） | 0.5–1.1 s | 0 | 端点很轻 |
| 识别（墙钟约 110 ms） | 350–390 ms | 0 | 大约三核 |
| 生成（墙钟 0.6–0.7 s） | 30–40 ms | 820–930 ms | 约 1.3 核，其余在 NPU |
| 合成（墙钟 32–49 ms） | 200–260 ms | 0 | 前段在 CPU，声码器在 NPU |
| 播放（墙钟 2.5–3.0 s） | 80–160 ms | 0 | 等声卡 |

A55、A76、NPU 全程锁在定频，没有降频。DDR 空闲 528 MHz，生成和合成期间 1848 MHz，播放时又落回 528 MHz。第一轮预填更慢，和它起步时内存还在低频一致。

启动日志里的 ONNX「找不到 GPU」「删掉未使用初始值」不影响结果。RKNN 已在 rk3588 上加载：runtime 2.3.2，驱动 0.9.8，目标 RKNPU v2。

## 六、这三轮说明了什么，还没说明什么

**说明了的：**

1. 半双工实麦能闭环。判停、识别、生成、合成、播放都走到了，没有段失败。
2. 用户可感的计算延迟约 0.85 秒，瓶颈是吐字。按 12.2 token/s，20 个 token 的回答光吐字就要约 1.6 秒，出声会到两秒以上。当前回答只有 4–6 个 token，所以还停在一秒以内。
3. 端点和听帧有余量。再优化 VAD 前向，出声时间几乎不动。100 ms 静音门限决定「什么时候算说完」，它已含在等待里。
4. 内存稳定，顺序执行时四段放得下。10 月 5 日「顺序跑时争用不是大头」的结论在实麦上仍成立。

**还没说明的：**

1. 识别率。三句是同一次现场，没有安静 / 嘈杂对照，也没有标注集。
2. 回答是否可用。同一句「今天去干嘛？」第一次答「我去图书馆看书。」，第二次把问题换了个说法；第三次「那你试着大声一些吧！」扣住了原话。预填 token 数不随轮次增长，多轮记忆这次没有测到，因为根本没送历史。
3. 唤醒和阵列。`serve.py` 的「小艺小艺」、八路麦、命令词「停止」都不在这份日志里。
4. NPU 利用率、温升、连续半小时功耗。占用文件没有权限，这次也没有跑长稳。
5. 吐字和声码器叠在一起的税。实麦是整句生成完再合成。10 月 5 日叠跑时，声码器挡住的那一个 token 间隔从 68 ms 拉到 104 ms；那笔账不能从这份日志里再算一遍。

**下一步**若要缩短用户等待，杠杆在生成：限制回答长度，或让声码器在吐字未结束时吃进已经写完的小句。听帧和合成再挤，0.85 秒里挪不动一百毫秒。
