# AI模型基础概念与分类——Transformer、BERT与端侧部署选型

## 核心摘要

模型本质上是一个"映射函数"（y = f(x)），通过海量数据训练出的网络权重来压缩现实规律。从工程落地角度，模型可按数据模态、输出目标、学习范式、部署规模四个维度分类。Transformer 是当代 AI 的基石架构，分化出 Encoder-only（BERT，擅长理解）与 Decoder-only（GPT/LLM，擅长生成）两大流派。在意图识别等实时场景中，端侧 BERT 小模型（5~20ms）仍是工业界主力，RK3588 等边缘芯片需经过 INT8 量化与 RKNN 转换才能高效运行。

---

## 一、模型是什么：工程视角的定义

在传统软件工程里，逻辑是"程序员写死规则 + 输入数据 = 结果"；而在 AI 工程里，逻辑变成了"海量输入数据 + 期望输出 = 算法自动学习出模型"。

通俗来说，模型就是一个**超级复杂的"黑盒公式"**，包含三个核心要素：

- **输入（x）**：一张图片的像素矩阵、一段音频信号、一句文字，或机器人的传感器数据。
- **计算（f）**：模型内部包含成千上万甚至上万亿个"权重参数"（Weights & Biases），这些参数是模型在训练阶段看过了海量数据后，自己总结出来的"内在规律"。
- **输出（y）**：分类结果、预测数值、生成内容等。

对于一个实际部署的模型文件（`.pt`、`.safetensors`、`.onnx`、`.rknn`），本质上就是把复杂业务问题转译为数学问题后，用训练出的网络权重去解决问题的工具。

---

## 二、模型的四维分类法

AI 模型种类多，按工程应用、技术架构和学习范式，可划分为以下四个核心维度。

### 2.1 按数据模态分类（工程落地最常用）

这是实际开发中最直观的分类，决定了输入输出的形态：

| 模态类型                  | 代表任务                      | 典型模型/架构                                     |
| :-------------------- | :------------------------ | :------------------------------------------ |
| **文本/语言模型(NLP）**      | 文本生成、语义理解、对话、翻译、代码编写      | GPT 系列、Llama、Qwen（Transformer Decoder-only） |
| **视觉模型（CV）**          | 图像分类、目标检测、语义分割、图像生成       | ResNet、YOLO、ViT、Diffusion Models            |
| **语音模型（Audio）**       | 语音识别（ASR）、文本转语音（TTS）、声音克隆 | Whisper、SenseVoice、CosyVoice、FastSpeech     |
| **多模态模型（Multimodal）** | 看图说话、图文生成、音视频端到端交互        | GPT-4o、Qwen-VL、Gemini、CLIP                  |
| **结构化/表格数据模型**        | 销量预测、违约率预测、推荐排序           | XGBoost、LightGBM、Random Forest              |

### 2.2 按输出目标分类：判别式 vs 生成式

这是工业界最常用的二分法，决定了模型的"工作方式"：

- **判别式模型（Discriminative）**：学习条件概率 P(Y|X)，专注分类、回归、检测。不关心数据如何产生，只关心如何区分。典型代表：YOLO（目标检测）、ResNet（图像分类）、XGBoost（风险预测）。
- **生成式模型（Generative）**：学习联合概率分布 P(X,Y) 或 P(X)，能够创造全新数据。典型代表：LLM（文本/代码生成）、Diffusion/GAN（图片/视频生成）、VALL-E（语音合成）。

一句话总结：判别式决定"是什么/在哪"，生成式创造"新数据"。

### 2.3 按学习范式分类

模型怎么被训练出来，直接决定了能力上限和数据需求：

- **监督学习（Supervised）**：给定明确的"输入-标签"对，如带人工标注的猫狗图片。
- **自监督学习（Self-Supervised）**：**现代大模型的核心动力**。无需人工标注，直接用海量无标签文本做"完形填空"或 Next-Token Prediction。GPT、Llama 等 LLM 均基于此范式。
- **强化学习（RL）**：模型作为 Agent 在环境中试错，获得奖惩信号后优化策略。典型案例：AlphaGo、大模型对齐阶段的 RLHF/DPO。
- **无监督学习（Unsupervised）**：没有标签，让模型自发发现数据内在结构（如聚类、降维）。

### 2.4 按部署规模分类：云端 vs 端侧

在硬件落地（嵌入式、机器人、云端服务）时，按参数量和计算复杂度划分：

| 类型           | 参数规模                   | 硬件要求                       | 典型场景               |
| :----------- | :--------------------- | :------------------------- | :----------------- |
| **超大规模云端模型** | 70B ~ 1000B+           | 多卡 GPU 集群                  | 复杂推理、对话、代码生成       |
| **端侧/轻量化模型** | 0.5B ~ 7B（量化后可压至几十 MB） | 边缘芯片（RK3588、Jetson、手机 NPU） | 离线 ASR、本地意图识别、实时控制 |

端侧模型的核心追求：低延迟、低功耗、高实时性、隐私安全。

## 三、Transformer 与 BERT：理解型与生成型的分水岭

### 3.1 Transformer 为什么是划时代架构

在 Transformer（2017，Google）出现之前，NLP 主流使用 RNN/LSTM，存在两个致命痛点：

1. **无法并行计算**：处理第 N 个词必须等第 N-1 个词算完，训练极慢。
2. **长距离遗忘**：句子一长，前面的信息被稀释。

Transformer 通过 **Self-Attention（自注意力机制）** 破解了这两个难题：一口气把整段文本扔进 GPU 并行计算，且无论两个词隔多远，注意力机制都能一步建立联系。

标准的 Transformer 包含两个核心部分：**Encoder（编码器）** 和 **Decoder（解码器）**。

### 3.2 BERT：Encoder-only 的理解型旗舰

**BERT**（2018，Google）是 Transformer Encoder 的经典应用。它的核心创新在于：

- **双向上下文理解**：BERT 能同时看清一个词的前后文。例如"苹果"在"吃苹果"和"买苹果手机"中含义不同，BERT 的双向注意力可以精准区分。
- **自监督预训练**：通过两个任务——MASK 掩码语言模型（完形填空，随机遮住 15% 的词让模型猜）和下一句预测（NSP）——在海量无标注文本上学习。

### 3.3 Transformer 三大流派的演进

原版 Transformer（Encoder + Decoder）后来分化出三条路线：

| 架构流派                | 代表模型           | 注意力方式                   | 核心优势           | 当前地位                  |
| :------------------ | :------------- | :---------------------- | :------------- | :-------------------- |
| **Encoder-only**    | BERT、RoBERTa   | 全句双向                    | 文本理解、分类、语义匹配   | RAG Embedding、意图识别的主力 |
| **Decoder-only**    | GPT、Llama、Qwen | 单向（只看左边）                | 自回归生成、逻辑推理     | LLM 时代的绝对统治者          |
| **Encoder-Decoder** | T5、BART        | Encoder 双向 + Decoder 单向 | 翻译、摘要（长输入→长输出） | 逐渐被 Decoder-only 统一   |

**关键认知**：BERT 和 GPT 虽然都是 Transformer 的后代，但走的路线完全不同——BERT 精于"理解"，GPT 精于"生成"，两者在工程中并不互斥��而是各司其职。

## 四、意图识别实战：BERT 为什么是工业界首选

### 4.1 意图识别的本质

意图识别是一个经典的**多分类任务**：根据用户输入的一句话，打上标签（如 `play_music`、`order_status`、`turn_on_light`）。BERT 架构在这个任务上有天然优势：

1. **双向上下文理解**：能精准捕捉否定词（如"不要播放音乐"中的"不要"）和语义转折，比 LLM 自回归机制更准确。
2. **极低推理延迟**：BERT 轻量化模型（TinyBERT、MobileBERT，10~30M 参数）在 CPU 或边缘芯片上仅需 **5~20ms**，而 LLM 至少需要几百毫秒甚至上秒。
3. **输出确定性**：搭配 Linear + Softmax 分类头，输出确定性的概率向量，不会出现大模型的"幻觉"问题。
4. **意图+槽位联合抽取**：Encoder 可在顶部接两个 Head（句级分类 + Token 级序列标注），一次前向传播同时完成意图和槽位抽取。

### 4.2 工业界实战做法

实际落地中很少直接用原生 `bert-base`（110M 参数，太重），常见变形方案：

- **中文优化版**：RoBERTa-wwm-ext、MacBERT、StructBERT，在中文 NLP 任务上效果优于原生 BERT。
- **轻量化端侧部署**：TinyBERT（4 层/6 层）、DistilBERT，参数量 10~30M，适合 RK3588、智能家居终端。
- **向量化匹配（无训练模式）**：用 BGE、M3E 等 Embedding 模型将用户输入编码为向量，在向量库中做余弦相似度匹配，新增意图时无需重新训练。

### 4.3 冷热分流架构

大模型（LLM）虽然泛化能力强，但在实时场景下不能替代 BERT。工业界标准做法是"双阶级"架构：

```
用户输入 → [1阶: 端侧轻量 BERT/向量匹配]
                │  90% 高频指令，<20ms，直接执行
                │
           (低置信度 / 复杂长文本 / 未定义意图)
                ↓
           [2阶: 云端 LLM 兜底]
                10% 复杂推理，深入理解并回复
```

第一道防线拦截 90% 以上高频固定指令，做到零延迟、零算力浪费；第二道防线处理复杂长对话和未定义意图。

## 五、端侧 vs 服务器部署：RK3588 实战对比

将同一个意图识别模型部署到 PC 服务器与 RK3588 端侧芯片，区别远不止"算力大小"，而是设计哲学、部署链路、资源瓶颈和优化策略的全方位差异。

### 5.1 核心差异对照

| 维度        | PC 服务器（云端/边缘服务器）                  | RK3588 端侧                        |
| :-------- | :-------------------------------- | :------------------------------- |
| **典型硬件**  | x86 CPU + NVIDIA GPU（4090/L4/A10） | ARM Cortex-A76/A55 + 6 TOPS NPU  |
| **内存与带宽** | 32~~512G DDR4/DDR5，显存 16~~80G     | 4~16G LPDDR4x/5，CPU 与 NPU 共享内存   |
| **计算精度**  | FP32、FP16、BF16                    | **INT8/INT16**（NPU 对 INT8 效率最高）  |
| **运行时环境** | PyTorch、ONNX Runtime、TensorRT     | **RKNN-Toolkit2 / RKNN Runtime** |
| **推理延迟**  | GPU 并行极快，但受网络传输影响                 | 本地计算，**5~15ms**，完全离线             |
| **功耗**    | 几百瓦到上千瓦                           | **5~15W**，被动散热                   |
| **网络依赖**  | 强依赖，网络抖动导致超时                      | **完全离线**，无网不影响核心控制               |

### 5.2 模型转化链路差异

- **服务器端**：导出 ONNX 或 TensorRT 编译，硬件兼容性好，算子支持丰富。
- **RK3588**：必须经 RKNN-Toolkit2 转换为 `.rknn` 二进制文件。NPU 对 Convolution、Linear、MatMul 支持好，但对特殊 Attention 变体或自定义层可能不支持，导致算子退化到 ARM CPU 运行，性能剧烈下降。

### 5.3 INT8 量化是刚需

- 服务器端可用 FP16 甚至 FP32 直接跑，量化只是为了提高吞吐量。
- RK3588 的 6 TOPS NPU 在 INT8 模式下才能发挥 100% 性能。必须准备好**校准数据集**，防止量化后分类概率剧烈偏移导致置信度失真。

### 5.4 模型选型与多任务共存

- 服务器端可直接用 `bert-base`（110M 参数），甚至 7B+ LLM 做复杂意图分类。
- RK3588 必须选用 TinyBERT（4/6 层）、MobileBERT 等 10~30M 参数量的极小模型，且需配合蒸馏（用服务器的 `bert-base` 做 Teacher，蒸馏出 Student 模型）。
- 端侧多任务共存（ASR + TTS + 视觉检测 + 意图识别），RK3588 的 3 个 NPU Core 需做好**多核心调度绑定**和**内存共享**，避免算力抢占。

### 5.5 推荐架构：端云协同

在实际产品设计中（智能机器人、离线语音中控），推荐方案：

- **RK3588 本地**：跑 TinyBERT（INT8 .rknn）或 Embedding + 向量库（FAISS/HNSW），处理 90% 固定域指令，响应 <10ms。
- **云服务器**：端侧判定低置信度（概率 < 0.6）时，异步上报至云端，由强力模型或 LLM 做复杂语义兜底。

## 六、总结

1. **模型是压缩规律的参数集合**：本质是 y = f(x) 的映射函数，选择哪类模型取决于业务场景、硬件算力和实时性要求。
2. **分类维度服务于工程决策**：数据模态决定输入输出形态，判别式/生成式决定能力边界，学习范式决定数据需求，部署规模决定硬件选型。
3. **Transformer 是当代 AI 的基石**，Encoder-only（BERT）擅长理解，Decoder-only（GPT/LLM）擅长生成，两者在工程中互补而非替代。
4. **意图识别走 BERT 路线**：高实时性、低成本、绝对确定性的场景，BERT + 微调仍是工业界最成熟的方案；LLM 适合做复杂兜底。
5. **端侧部署是系统工程**：RK3588 等芯片需要 INT8 量化、RKNN 转换、算子适配、多任务调度，远不止"换个硬件跑一下"。端云协同是当前最优解。
