# RK3588推理数据流：CPU缓存与NPU的DDR交接

**核心摘要**：RK3588 上 ONNX 只是计算图，不决定跑在 CPU 还是 NPU。转成 RKNN 后，CBUF 只暂存当前卷积的输入和权重，结果写到 DDR 或 SRAM，下一 task 再读回。BN、ReLU 留在 DPU，因为只处理刚算完的点。大卷积仍归 NPU；缓存命中或来回回退时才考虑 CPU。

> **口径**：下文的 2.0 ms、9.0 ms 是按峰值手算的教学账，用来把搬运和 MAC 拆开，不是某块板的实测。板上实测以同库《SileroVAD在RK3588上的CPU与NPU实测对比》为准。芯片理论内存带宽见《4090与RK3588硬件设计差异与原理》里的 34～51 GB/s，那是 CPU、GPU、NPU、ISP 共享的上限；本账里 NPU 实际分到的有效带宽按 10 GB/s 取整。

---

## 一、文件格式和执行路径是两件事

ONNX 描述算子和张量怎么连，里面没有「请用 CPU」这条指令。同一份文件在 RK3588 上只有两条真正会跑起来的路，格式差异见《PyTorch-ONNX-RKNN模型格式对比与转换链路》。

| 调用方式 | 谁在算 | 中间结果放哪 |
| --- | --- | --- |
| `rknn-toolkit2` 编成 `.rknn`，再 `rknn_run` | NPU 的 task | DDR，或划给 NPU 的系统 SRAM |
| ONNX Runtime 默认 CPU Execution Provider | CPU 内核 | 普通内存；热数据由 L1/L2/L3 自动截住 |

Rockchip 没有为 ONNX Runtime 写 NPU EP。板子上直接加载 `.onnx`，NPU 是闲的。

---

## 二、NPU 侧不要把三层存储看成一块缓存

| 层次 | 是什么 | 推理时放什么 |
| --- | --- | --- |
| DDR | 片外主存，与 CPU、GPU、ISP 共享 | 输入、输出、放不下的权重和中间特征 |
| 系统 SRAM | SoC 上约 1MB，最多约 956KB 可划给 RKNPU | 可选：Internal（中间特征）和 Weight（权重） |
| 核内 CBUF | 当前这一次 MAC 的工作缓冲，按 bank 切开 | 当前 tile 的输入特征和当前层权重 |

CBUF 装不下一整张特征图，也不会把「算子 1 的完整输出」留到算子 2。系统 SRAM 才是可选的中间结果驻留区；默认不划给 NPU 时，中间结果在 DDR。

权重在 `rknn_init` 时已经放进 Weight 内存。`rknn_run` 里只是按 tile 把它们 DMA 进 CBUF，不是每次从模型文件里读。

三核各有自己的 CBUF，核与核之间看不见对方的 bank。一条有依赖的链不能靠三核把单帧延迟打成三分之一，多核主要提高多帧吞吐。

## 三、读写发生在 task 边界，不发生在 ONNX 节点边界

编译器先做融合和内存规划，再把图拆成一串 task。RK3588 的卷积通路与 NVDLA 同类，单次 task 是单向的：

```text
DDR / 系统 SRAM
    │  DMA：当前 tile 的特征 + 当前层权重
    ▼
  CBUF
    ▼
  MAC → 累加器 → DPU / PPU（偏置、激活、池化）
    │
    ▼
DDR / 系统 SRAM     ← 本 task 的输出立方体
```

CBUF 里是这一层的输入切片和权重。MAC 的结果进累加器，融得进去的后处理在 DPU 里接上，然后整张输出写出。下一个 task 会重新划分 bank、重新灌入自己的权重，输入仍从内存 DMA 进来。

通道或空间尺寸超过 CBUF 时，同一层自己就要分 tile：读一块、累加、再读下一块。下一块还能用同一份权重时，权重留在 CBUF 里。这是层内复用，范围到这一层算完为止。

因此「从内存读到片上、算完、写回」发生在 task 边界。ONNX 里相邻的 Conv、BN、ReLU 若收成一个 task，中间值不落内存。

### 3.1 十个融不成一个 task 的节点

五个算子种类不进入次数。次数只由 task 个数，以及每个 task 要读、写的张量个数决定。

十条一元链、中间结果在 DDR、按张量计（不按 DMA 突发计）：

```text
读 in  → task1 → 写 m1
读 m1  → task2 → 写 m2
...
读 m9  → task10 → 写 out
```

| 张量 | DDR 读 | DDR 写 |
| --- | ---: | ---: |
| 网络输入 in | 1 | 0 |
| 中间特征 m1…m9 | 9 | 9 |
| 网络输出 out | 0 | 1 |
| 合计 | 10 | 10 |

Internal 内存池可以复用同一块物理地址，那只减少占用。m3 写完后地址可以给后面的张量用，但 m3 该写的一次、该读的一次都还在。

每个带权重的节点再加 1 次权重读。十层都有独立权重时，20 次特征访问加上 10 次权重读，共 30 次。某个节点是两个输入（例如 Add），那个 task 多 1 次特征读。

CBUF 装不下时，同一次逻辑读写会拆成多笔 DMA，笔数取决于切分，没有固定值。中间特征若命中系统 SRAM，对应的那一对读写改走 SRAM，日志里的 `SramHit` 就是这一层实际命中的大小。

## 四、用同一组数字把墙钟走完

教学假设，便于心算：

| 项目 | 取值 |
| --- | --- |
| 执行 | 1 个 NPU 核，task 依依赖串行 |
| 单核算力 | 2 TOPS INT8。1 次 MAC 按乘加 2 次运算计，即每秒 \(1\times10^{12}\) 次 MAC |
| 有效带宽 | \(10\,\text{GB/s}\)。理论总线更高，这里只取 NPU 这份 |
| 重叠 | 同一 task 内 DMA 与 MAC 重叠，本层耗时取两者较大值；层与层不重叠 |

模型是 10 层相同的 Depthwise \(3\times3\)，形状不变。每层特征 \(100\times100\times100 = 1\,000\,000\) 字节，权重 \(100\times3\times3 = 900\) 字节，MAC 次数 \(1\,000\,000\times9 = 9\times10^{6}\)。

\[
\frac{1\,000\,000}{1\times10^{10}} = 100\,\mu\text{s}
\]

| 步骤 | 数据量 | 时间 |
| --- | --- | ---: |
| 读输入特征 | 1 MB | 100 µs |
| 读权重 | 900 B | 0.09 µs |
| MAC | \(9\times10^{6}\) 次 | 9 µs |
| 写输出特征 | 1 MB | 100 µs |

搬运约 200 µs，计算 9 µs。本层墙钟取 **200 µs**。十层为 **2.0 ms**。

```text
0 µs      task1 读 in
200 µs    task1 写 m1
300 µs    task2 读 m1     ← 刚写下去的那 1 MB
500 µs    task2 写 m2
...
2000 µs   task10 写 out
```

m1 从 task1 交到 task2，单独就是写 100 µs 加读 100 µs。九张中间特征这样交接，共 1.8 ms。对外部可见的只有开头读 in 和最后写 out，共 0.2 ms。MAC 合计 0.09 ms，被搬运盖住。

把算子换成普通 \(3\times3\) 卷积，输入输出通道都是 100，特征仍是每层 1 MB。每层 MAC 变成 \(1\,000\,000\times900 = 9\times10^{8}\) 次，权重变成 90 KB。

| 步骤 | 时间 |
| --- | ---: |
| 读特征 1 MB + 读权重 0.09 MB + 写特征 1 MB | 209 µs |
| MAC | 900 µs |
| 单层墙钟 | 900 µs |
| 10 层 | **9.0 ms** |

DDR 仍然是那 20 次特征读写。Depthwise 用来看清内存交接，普通卷积用来看清算力。算术强度的一般形式见《内存带宽为何决定解码速度》。

带宽提高一倍，2.0 ms 里的搬运时间减半。实际利用率到不了 100%，同一套数据在板上常见再放大到大约 2～5 倍，数量级仍是几毫秒。

## 五、CBUF 为什么不把结果留给下一个 task

放不下是原因之一。1 MB 的整张特征进不了只为当前 tile 准备的 bank；通道一多，同一层卷积自己都要分多次灌入。更根本的是结果根本不写进 CBUF。

即便某一层输出只有几十 KB，下一个卷积仍然用不上：

- 布局不对。bank 里的排列是上一层输入和上一层权重。下一层要的是上一层的输出，还得换成自己的通道分组和卷积核窗口。
- 位置被占用。下一次 MAC 必须把新权重放进这些 bank。
- 卷积要邻域。下一个 \(3\times3\) 的一个输出点要用周围一圈像素，这些像素往往不属于刚刚算完的那一块 tile。

「算完直接留给下一步」在同一次 task 里已经发生：tile 之间可以复用权重；Conv 后面的 BN、ReLU 若融进 DPU，中间值停在累加器到 DPU 的流水里。两个卷积融不成这种流水时，中间必须变成一张可再次 DMA 的特征图。想少走 DDR，就把它放到系统 SRAM 上，让下一个 task 的 DMA 从那里读。

## 六、BN 和 ReLU 为什么融得进 DPU

能融进去，是因为这两个算子都只处理卷积刚算完的那个输出点，而 DPU 就接在累加器后面。和「有没有权重」关系不大。

ReLU 没有权重，就是对每个数做 \(\max(x, 0)\)。BN 在推理时有参数，每个输出通道一组 scale 和 bias，只是远小于卷积核。

INT8 卷积先把一个输出点累加成 INT32。DPU 从这里把数接走，按通道乘 scale、加 bias、做 ReLU 或截断，再量化回 INT8，然后才写内存。

BN 的推理形式和这第一步相同：

\[
z = \gamma \frac{y - \mu}{\sigma} + \beta = s \cdot y + b
\]

\(s\) 和 \(b\) 每个通道各一个。编译期会把 \(s\) 再乘进卷积权重，偏置收成一个数。运行时 DPU 上看到的，是合并之后的每通道乘加，再接 ReLU。

下一个卷积融不进来，是因为它要另一套核权重，还要周围一圈像素，必须重新把特征灌进 CBUF 再走一遍 MAC。DPU 没有卷积阵列，也看不到这个点的空间邻居。

## 七、CPU 上调度同构，缓存是自动的

CPU 执行器在 kernel 边界上是同一类交接：上一个 kernel 把输出写入一块缓冲区，下一个 kernel 再把它当输入。图优化仍会把 Conv+BN+ReLU 收成一次调用，文件里的 10 个节点往往不是 10 次函数调用。缓冲区复用同样只省空间。

差别在缓存。CPU 没有单独的 CBUF，也不为每个算子做一次显式 DMA。A76 每个核有自己的 L1、L2，四个大核共享约 3MB 的 L3。上一个 kernel 刚写完的数据如果还在这些缓存里，下一次读命中缓存，DRAM 上看不到这次往返。

仍用那张 1MB 的特征：它小于约 3MB 的 L3，十层串行、缓冲区还热的时候，m1 的「写然后读」多半停在 L3。特征若是 20MB，装不进 L3，每次写出去再读回来就会真正进出 DDR，形态上才接近「每个节点读写一次内存」。

NPU 那边即使中间特征只有 1MB，只要没放进系统 SRAM，task 边界仍是编译器安排的 DDR 读写。

还有一层容易漏掉的损失：ONNX Runtime 在 CPU 上默认常按 FP32 算。同样一层卷积，计算量和内存流量都比 NPU 上的 INT8 大。要和 NPU 比速度，CPU 侧也得是同一套 INT8，并走到 XNNPACK 或 ARM Compute Library。

## 八、搬运变多以后，怎么选执行器

搬运次数多，会把 NPU 相对 CPU 的加速比拉低。拉低之后，主体是大卷积的网络仍然是 NPU 更快。

用第四节的账，再给 CPU 一个教学假设：一个 A76 做这种 Depthwise 时，INT8 有效吞吐按每秒 \(2\times10^{10}\) 次 MAC 估（到不了理论峰值）。全网 \(9\times10^{7}\) 次 MAC 大约要 4～5 ms。NPU 那条链是 2.0 ms，优势只剩大约两倍，四个大核一起算才有机会接近。普通卷积全网 \(9\times10^{9}\) 次 MAC，NPU 约 9 ms，一颗 A76 按同一量级要到 100 ms 以上。

真正让 NPU 更慢的，是 task 碎、而且编译器收不拢。同库 Silero VAD 的实测就是这个形状：图被拆成大约 65 次 Conv，单帧墙钟 1.483 ms，绑在一颗 A76 上的 ONNX 是 0.206 ms，NPU 慢约 7.2 倍。标称 6 TOPS 在这种图上没有意义，时间花在提交、布局转换和碎核启动上。

适合留在 CPU 上的是这三类：

- 很多算子 NPU 不支持，图在 NPU 和 CPU 之间来回切。每次交接都要同步再走 DDR，通常比整网留在 CPU 更慢。
- 模型很小，任务提交和启动已经超过计算本身。
- 全部中间特征都进得了 L3，而且几乎都是逐元素、Depthwise 这种低计算密度，实测 CPU 更短。

搬运已经占满时间时，先减少 task 边界：能融合的合成一个 task，中间特征和权重放进系统 SRAM。看每层 MAC 利用率和带宽：

```bash
export RKNN_LOG_LEVEL=4
export RKNN_INTERNAL_MEM_TYPE=sram
export RKNN_SEPARATE_WEIGHT_MEM=1
export RKNN_WEIGHT_MEM_TYPE=sram
```

`RKNN_LOG_LEVEL=4` 时，每层会打出 MAC 利用率和带宽；内存报告里的 `SramHit`、`Predict SRAM Hit RW Amount` 用来估计这一帧少走了多少 DDR。SRAM 只有几百 KB，大特征图仍然主要在 DDR。MAC 利用率高就留在 NPU；带宽打满且 task 很碎，先融合、上 SRAM，再用同一输入对 `rknn` 和 ONNX Runtime 各计一次墙钟。
