# LLM部署选型参数怎么看-以Qwen2.5-1.5B为例

部署者读模型参数，不是为了懂算法，是为了算四笔账：装不装得下（显存）、聊得多久（上下文）、喂得进吗（接口）、跑多快（速度）。四笔账算清，一个模型该不该上板子就定了七八成，剩下的交给实测。config.json 是唯一权威，本文全部数字以官方 config.json 核对（huggingface.co/Qwen/Qwen2.5-1.5B）。

## 一、config.json 是唯一权威

不读博客、不读营销页，先读 config.json。需要重点看的字段一共 8 个：

| 字段 | Qwen2.5-1.5B 的值 | 服务于哪笔账 |
|---|---|---|
| architectures / model_type | Qwen2ForCausalLM / qwen2 | 接口账 |
| num_hidden_layers | 28 | 显存账（KV） |
| hidden_size | 1536 | 结构档位 |
| num_attention_heads | 12 | 结构档位 |
| num_key_value_heads | **2** | 显存账（KV），最值钱的一个 |
| head_dim | 128（推导值） | 显存账（KV） |
| max_position_embeddings | 131072 | 长度账 |
| dtype | bfloat16 | 显存账（权重） |

辅助看两个：vocab_size = 151936（词表大小）、tie_word_embeddings = true（输入输出共享 embedding，省约 2.33 亿参数）。

注意 head_dim 的来源：config 里**没有**这个字段，由 hidden_size ÷ num_attention_heads = 1536 ÷ 12 = 128 推出，可用权重文件里 K/V 张量的实际 shape 复核。

## 二、显存账：权重 + KV 两条腿

### 权重账

总参数约 1.54B，构成如下（每层的数 × 28 层，再加 embedding）：

| 部件 | 单层参数量 | 说明 |
|---|---|---|
| Wq | 2.36M | 1536×1536 |
| Wk + Wv | 0.79M | 1536×256 各一，**GQA 把 12 组压到 2 组，这里省 6 倍** |
| Wo | 2.36M | 1536×1536 |
| FFN（SwiGLU 三矩阵） | 41.3M | 1536×8960 ×3，**参数大头在 FFN，占约 87%** |
| Embedding | 2.33 亿（全模型一份） | 151936×1536，tie 后只存一份 |

权重显存 ≈ 参数量 × 每数几字节：

- BF16/FP16（2 字节）：约 3.1 GB
- INT8（1 字节）：约 1.5 GB
- INT4（0.5 字节 + 量化开销）：约 0.9-1.0 GB

### KV cache 账

```
KV = 2 × 层数 × kv_head × head_dim × seq × 字节
   = 2 × 28 × 2 × 128 × seq × 2B（FP16 口径）
   = 28 KiB / token，即每 1K token 约 28 MB
```

公式里只有 seq 是活的，其余四项训练完就焊死。代入几个典型长度：

| seq | KV 显存（FP16） |
|---|---|
| 1K | 28 MB |
| 4K | 约 115 MB |
| 16K | 约 470 MB |
| 32K | 约 0.92 GB |
| 128K（官方上限） | **约 3.76 GB，比权重还大** |

cache 里存的是每层每 token 的 K、V 成品（各 2 个 128 维向量），不是 hidden 半成品——存成品省 3 倍空间还免重复投影。

**8GB 板子的直接结论**：权重上 INT4（约 0.9 GB）+ 语音对话把 seq 限在 2K-4K（KV 约 60-115 MB），两条都留足余量；开满 128K 纯属想多了。

## 三、长度账

- **max_position_embeddings = 131072**：训练时见过的最大位置编号，官方保修长度的红线。注意这是**模型能力的边界**，不是产品参数——真实可用 seq 要按 KV 显存反推，远小于它。
- **上下文是全序列共用的**：系统提示 + 历史对话 + 本轮输入 + 模型已输出，全占同一个 seq。模型输出越写越长，KV 同步膨胀。
- **超了上限不会立刻报错**：RoPE 会外推，但质量劣化（重复、跑题），端侧别赌框架兜底，闸要自己装：`max_new_tokens` 限输出、历史轮数限输入。
- **rope_theta = 1000000**：RoPE 打位置戳的基底频率，决定长距离位置分辨能力。大 theta 是为长上下文调的（默认值 10000 的 100 倍），平时不用管，只在对比各家 context 宣称时瞄一眼。

## 四、接口账

- **model_type: qwen2**：推理框架支持列表的第一判据——RKNN、llama.cpp、MNN 能不能跑，先对架构名。
- **vocab_size: 151936**：词表大小，决定 embedding 显存（151936 × 1536 × 2B ≈ 0.47 GB，BF16）和多语种覆盖。
- **head_dim 必须在 Q/K 之间相等**（点积配对锁死），V 的维度其实可以不同但惯例统一 128。看到别的模型 head_dim 是 64 或 96，公式照样套，替换数值即可。

## 五、速度账（顺带一笔）

- **Decode（出字）卡显存带宽，不卡算力**：每出一个 token 都要把全部权重重新读一遍。RK3588 的 LPDDR4x 实测带宽约 20 GB/s，理论上限 FP16 ≈ 6 token/s、INT4 ≈ 20 token/s——这是量化能提速的原因：省的不是计算，是搬运。
- **Prefill（首响）卡算力**：prompt 一次吃下，打分矩阵是 N×N（每头一张），首响延迟随 prompt 长度线性涨。**精简系统提示词是零成本的延迟优化**。
- 以上是理论上限，实测为准，NPU 调度和框架开销另扣。

## 六、明确不用看的参数

attention_dropout、initializer_range、transformers_version、use_cache、max_window_layers、sliding_window——全是训练或实现细节，对部署零决策价值。

## 七、动作：拿到新模型的三分钟体检

1. 打开 config.json，按顺序扫：model_type → 参数规模 → dtype → 层数 / kv_head / head_dim → max_position_embeddings → vocab_size / tie_word_embeddings；
2. 写一行账：`权重 X GB（FP16）/ INT4 约 Y GB + KV 每 1K token Z MB + context 上限 W`；
3. 对照板子：显存装不装得下、目标 seq 时 KV 多大、框架认不认 model_type；
4. head_dim 或任何维度存疑时，回 safetensors 里实测张量 shape，以权重为准。

写得出那行账，选型决策的账面部分就完成了；写不出，缺的就是表里某一项。

## 附：Qwen2.5-1.5B 一行账（本文结论）

> 权重 3.1 GB（FP16）/ INT4 约 0.9 GB + KV 每 1K token 28 MB（FP16）+ context 官方上限 128K（8GB 板上实际按 2K-4K 设计）+ decode 理论上限 FP16 约 6 token/s、INT4 约 20 token/s（20 GB/s 带宽口径）。

**要点回顾**：KV 公式里活变量只有 seq；kv_head 是选型最值钱的结构参数；官方 context 上限不等于产品可用长度；decode 瓶颈在带宽所以量化既省显存又提速；prefill 瓶颈在算力所以砍 prompt 就是砍首响。
