# 腾讯小龙虾-网页爬取与部门文档生成

## 核心摘要

腾讯小龙虾（WorkBuddy）的网页抓取 + 文档生成能力，将传统"人工搜索→复制粘贴→整理排版→翻译改写"的链条压缩为一次自然语言指令。本文记录利用它爬取阿里云百炼平台技术文档，为销售部生成语音选型指南、为研发部生成开发参考文档，以及为补贴部门生成申报材料的完整实践。

---

## 一、问题背景

在日常工作中，面向不同部门的文档产出存在三个核心痛点：

1. **信息获取成本高**：技术文档分散在多个页面，人工逐页阅读、提取、汇总耗时长。以阿里云百炼的 Qwen3 TTS 为例，音色列表、语种支持、API 参数分布在多个子页面，整理一份完整的参考文档至少需要半天。
2. **多部门视角切换繁琐**：同一份原始资料，给销售部要突出"卖点"和"可选项"，给研发部要侧重"接入方式"和"参数约束"，给补贴部门则要强调"技术先进性"和"创新指标"——三份文档面向三拨人，信息密度和侧重点完全不同。
3. **补贴申报文档的格式要求严格**：政府补贴、项目申报材料对文档格式、技术指标描述、创新点罗列有固定范式，手动整理容易遗漏关键字段或格式不合规。

腾讯小龙虾恰好在这三个环节提供了端到端的自动化方案。

---

## 二、腾讯小龙虾的核心能力定位

腾讯小龙虾（WorkBuddy）本质上是一个具备**联网搜索 + 网页内容抓取 + 多模态理解 + 结构化文档生成**能力的 AI Agent。与常规聊天模型不同，它的关键差异在于：

| 能力 | 常规聊天模型 | 腾讯小龙虾 |
|------|-------------|-----------|
| 网页抓取 | 依赖用户粘贴链接和内容 | 自主访问 URL，解析页面，提取结构化信息 |
| 上下文范围 | 受单次对话窗口限制 | 可跨多个 URL 聚合信息，形成完整知识视图 |
| 文档产出 | 仅输出对话文本 | 生成带格式的 Markdown/文档文件，存入项目目录 |
| 角色切换 | 需要显式指定 | 同一份素材可按不同角色视角重新组织输出 |

**本质区别**：它不是"我问你答"，而是"给我一个任务，我帮你把信息找回来、整理好、写出文档"。

## 三、实战案例一：为销售部生成语音选型文档

### 3.1 任务描述

销售团队需要一份面向客户的 Qwen3 TTS 语音能力说明文档，核心诉求是：支持哪些语种、有哪些音色可选、每种音色的适用场景，语言要通俗，便于销售人员直接引用和向客户展示。

### 3.2 执行过程

向腾讯小龙虾下达指令：

> 帮我看看 Qwen3 TTS 支持的语种有什么，结合阿里云百炼的官方文档整理一份面向销售部的语音选型参考指南。

小龙虾自动访问了阿里云百炼平台的 Qwen TTS 音色列表页面（`https://help.aliyun.com/zh/model-studio/qwen-tts-voice-list`）及相关开发文档，提取了以下关键信息：

- **语种覆盖**：中文、英文、日语、韩语、粤语等十余种语言及方言
- **音色分类**：按性别（男/女）、年龄（成人/童声）、风格（新闻播报/客服/闲聊/故事讲述）多维度归类
- **适用场景映射**：客服场景推荐 X 音色，教育场景推荐 Y 音色，营销场景推荐 Z 音色

最终生成了一份结构化的 Markdown 文档，包含音色对照表、适用场景建议和选型决策树，销售人员可直接复制到客户提案中使用。

## 四、实战案例二：为研发部生成开发对接文档

### 4.1 任务描述

研发团队需要的是技术层面的接入文档，而非市场导向的选型指南。核心诉求：API 调用方式、参数说明、音色 ID 对应表、语种代码映射、调用频率限制等。

### 4.2 执行过程

同样以阿里云百炼平台的 Qwen TTS 官方文档为数据源，下达了技术导向的指令：

> 整理 Qwen3 TTS 的完整音色列表和 API 调用参数，生成一份面向研发人员的开发参考文档。

小龙虾自动完成了：
- 提取所有音色的唯一 ID、名称、语种标签
- 整理 API 端点、认证方式、请求/响应参数结构
- 按语种分组排列，补充每种音色的 `voice_id` 和推荐采样率
- 标注了官方文档中未显式说明但实际存在的约束（如部分音色仅支持特定地域节点）

## 五、扩展到补贴部门文档的生成思路

以上两个案例已经验证了"一次爬取 → 多份文档"的可行性。补贴/政府项目申报场景的文档需求可以在此基础上进一步扩展：

### 5.1 典型流程

```
原始资料（技术文档、产品白皮书、专利列表）
    │
    ├──→ 销售部文档（卖点 + 对比 + 场景）
    │
    ├──→ 研发部文档（API + 参数 + 约束）
    │
    └──→ 补贴部门文档（创新指标 + 技术先进性 + 经济价值）
```

### 5.2 补贴文档的特殊要求

补贴申报文档通常需要满足以下格式规范，这些都可以通过提示词约束让小龙虾自动完成：

| 要素 | 内容来源 | 小龙虾的处理方式 |
|------|---------|-----------------|
| 技术指标表 | 从文档中提取数值化指标 | 自动整理为"指标名称 / 数值 / 行业对比"三列 |
| 创新点罗列 | 从产品描述中归纳 | 按"技术突破 / 应用创新 / 模式创新"三类归并 |
| 经济价值预估 | 结合市场份额数据 | 接入公开行业报告，给出基于数据的估值区间 |
| 知识产权佐证 | 提取专利/软著号 | 自动检索专利数据库补充状态信息 |
| 格式合规 | 政府模板要求 | 以 `Constraints` 约束输出结构、字数、表格格式 |

### 5.3 实操建议

1. **预先建立资料库链接清单**：将需要用到的官方文档 URL、行业报告链接、专利数据库查询入口整理成一个清单，直接喂给小龙虾。
2. **角色化提示词**：明确"你是补贴申报材料撰写专家，熟悉 XX 地区 XX 类项目的申报范式和评审要点"，让输出更贴合实际评审标准。
3. **多轮迭代**：首轮生成框架 → 人工校验关键数据和表述 → 第二轮微调措辞和格式 → 输出终稿。人工审校环节不可省略，AI 负责"快速粗加工"，人负责"精准把关"。

## 六、延伸思考

### 6.1 成本收益

以 Qwen3 TTS 文档整理为例：传统方式下，一个人工整理完销售版 + 研发版两份文档大约需要 4～6 小时（搜索 30 分钟、阅读 1 小时、整理撰写 2～3 小时、排版校对 30 分钟）。通过小龙虾，指令下达到文档交付不超过 5 分钟，人工只需做一次快速审校。效率提升约 **50～70 倍**。

### 6.2 局限与注意

- **网页内容依赖原始准确性**：如果源头文档有误或过时，小龙虾不会主动纠错，只忠实反映原文。关键数据（如 API 参数、音色 ID）需人工抽样验证。
- **补贴文档的法律合规**：政府补贴申报涉及法律责任，AI 生成内容只能作为草稿框架，最终提交版本必须由专业人员逐条核实。
- **动态页面抓取受限**：部分需要登录、验证码、或强 JavaScript 渲染的页面，小龙虾的静态抓取能力有限，需要手动提供文本内容作为输入。

### 6.3 核心洞察

腾讯小龙虾的真正价值不在于"更聪明的搜索"，而在于**把信息获取和文档产出两个独立环节无缝衔接**。传统工作流中，"查资料"和"写文档"由同一个人在不同时间段完成；小龙虾将其合并为一步——信息找到了，文档也就写好了。这是工作方式上的质变，而非简单的效率提升。
