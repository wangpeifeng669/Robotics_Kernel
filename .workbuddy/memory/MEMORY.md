## 文章规范要点（来自 README.md）
- 无需 frontmatter，正文直接以 H1 标题开头
- 正文开头必须有核心摘要（≤150 字），2-4 句话讲清楚结论
- 文件命名：YYYY-MM-DD_<简短主题标识>.md，中文为主，术语可用英文
- **H1 标题 = 文件名去掉日期部分**（如文件 `2026-07-08_三大国产TTS对比-MiniMax-Qwen3-豆包.md` → H1 `# 三大国产TTS对比-MiniMax-Qwen3-豆包`）
- 标题语言：正文各级标题用中文，专业术语缩写（ASR/LLM/TTS/INT4 等）除外
- 写作原则：先摘要后细节、可复现、数字说话、工程视角、精简不冗余
- **[用户反馈] 文章要控制复杂度**：用户嫌文章复杂时会明确要求删小节。反复出现的信号是——**别把「我怎么查证的」写进正文**。澄清类、辩驳类、佐证出处类（图解析表、报错原文、源码片段、外部issue 引用）适合留在工作记忆里，正文压缩成一句结论即可。保留的是：三关/主线的叙事骨架 + 实测数据表 + 判决条件。实测报告类文章控制在 200 行以内为宜（参见 2026-09-28 SileroVAD 篇：初稿 249 行被要求精简至 187 行）。
- **[用户反馈] 品类科普类内容要整节砍掉**（2026-10-04 内存基础篇）：内存品类科普（电气标准/封装互联/部署位置三维度分类、LPDDR4X vs LPDDR4 代次辨析）被整节删除，理由是**「对端侧部署没有作用」**——读者是来选型和排障的，不是来学内存分类学的。**判据：只有能推动「用不用 / 用哪个 / 怎么测」的内容才进正文，品类背景知识一律砍。** 被删的洞察若在正文别处被引用（如 RK3588 vs RK1828 对比表里的内存类型列），则在速查块保留一行结论，不展开。
- **[用户反馈] 方案类文章的主线要求**：写"某系统的方案/架构"类文章时，**必须以架构调整叙事为主线**（调整前现状 → 现场后果 → 根因 → 调整后分层 → 逐层明细 → 前后对照 → 验收口径）。单点原理深挖（如数学推导、参数依据）只能作为其中一层的支撑，不能占满全文——用户明确反馈过"太技术性了，没有说明整个方案的调整"。参见 2026-09-17 本地机器人群控架构调整（第一版被推翻重写）。
